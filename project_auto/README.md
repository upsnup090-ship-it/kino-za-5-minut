# Кино за 5 минут

**Важные изменения**:
- Время в главном меню теперь фиксировано на московском часовом поясе (`Europe/Moscow`).
- Все HTTP-запросы идут через `kino/net_guard.py` (allowlist-классы read/llm/publish/proxy/loopback, только https, без редиректов); см. «Безопасность».
- Временные файлы пишутся в `.tmp/` внутри проекта, не в `/tmp`.

Telegram-бот автопубликаций о кино. Собирает новости (RSS/Atom или дайджест
Horizon), выбирает тему и формат, пишет черновик через LLM, проверяет вторым
вызовом, ищет картинку в Wikipedia и публикует в канал.

## Установка

```bash
python3.11 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp docs/env.example .env
```

Заполни `.env` реальными значениями. Без этого запуск невозможен.

При первом запуске в `CHANNEL_CHAT_ID` ставь **тестовый** канал. Боевой
подключай только после обкатки.

## Источник новостей

Два режима, переключаются через `SOURCE_MODE` (или `horizon.source` в
`config/settings.yaml`):

- **`rss`** (по умолчанию) — RSS/Atom из `config/sources.yaml`.
- **`horizon`** — запускает `uv run horizon`, читает свежий `.md` из
  `data/summaries/` и разбирает его в новости.

```bash
# RSS (по умолчанию)
python -m kino run

# Horizon
SOURCE_MODE=horizon python -m kino run
```

Для Horizon нужен клон в `horizon/` (или путь через `HORIZON_DIR`) и
установленный `uv`. Если их нет — скрипт сообщит внятной ошибкой, а режим
`rss` продолжит работать.

## Dry-run

По умолчанию ничего не публикуется и state не сохраняется:

```bash
cd /workspace/project
python -m kino run
```

Dry-run всё равно вызывает LLM и тратит токены. Он пропускает только
публикацию и запись state.

## Боевой запуск

```bash
cd /workspace/project
python -m kino run --publish
```

## Cron

Ежедневно в 12:00:

```cron
0 12 * * * cd /workspace/project && venv/bin/python -m kino run --publish >> logs/cron.log 2>&1
```

Cron — простейший вариант «один запуск — один пост». Для полноценного режима
24/7 есть `serve`: он сам следит за окнами публикации и суточным лимитом.

```bash
cd /workspace/project
python -m kino serve           # цикл 24/7 (на сервере — через планировщик задач)
python -m kino serve --once    # один проход цикла и выход (отладка)
```

## Команды

| Команда | Что делает |
|---------|-----------|
| `python -m kino run` | dry-run: собрать, сгенерировать, проверить — без публикации |
| `python -m kino run --publish` | боевой запуск: один пост |
| `python -m kino draft "тема"` | черновик по заданной теме (по умолчанию формат `news`) |
| `python -m kino draft "тема" --format review` | черновик конкретного формата |
| `python -m kino draft "тема" --format facts --dry-run` | печать тела запроса к LLM без вызова (проверка подстановки спецификации формата) |
| `python -m kino serve` | цикл 24/7 по расписанию |

## Форматы постов

16 форматов, веса — в `config/formats.yaml`. Спецификация каждого формата —
отдельный файл `prompts/formats/<fmt>.txt` (НАЗНАЧЕНИЕ, СТРУКТУРА, ОБЯЗАТЕЛЬНО,
ЗАПРЕЩЕНО, ПОЛЯ, ПРИМЕР); она подставляется в запрос к LLM. Реестр форматов и
их доставку см. в [`docs/architecture.md`](docs/architecture.md#форматы-постов).

## Обработка ошибок

- При ошибке 429 (Too Many Requests) бот автоматически делает паузу
  и повторяет отправку после времени, указанного Telegram API
- Максимум 5 попыток с экспоненциальной задержкой
- Сетевые ошибки также обрабатываются с повторами

## Безопасность

- Токены и ключи только в `.env`, который не коммитится.
- Логи не содержат токенов, ключей и chat_id.
- State сохраняется атомарно: временный файл (в `.tmp/`) + rename.
- Lock-файл защищает от параллельных запусков и перехватывается, если владелец
  умер (иначе под cron прогон встал бы навсегда).
- Dry-run не меняет state.
- **Сеть**: все HTTP-запросы проекта идут через `kino/net_guard.py` —
  классы `read` (RSS, Wikipedia, graph.org, quickchart.io), `llm`
  (хост `LLM_BASE_URL` валидируется при старте конфигом), `publish`
  (`api.telegram.org`), `proxy`, `loopback`. Внешние классы: только https,
  только FQDN из allowlist, IP-литералы и нестандартные порты запрещены,
  редиректы запрещены. Проверка: `python -m kino.net_guard --audit`.
- Классификация файлов проекта (`kino/klass.py`): ORIG / DERIV / STATE /
  SECRET / EXCLUDED — страховка и обращение с файлами определяются по пути,
  а не по намерению.

## sd_notify

`sd_notify` используется для взаимодействия процесса с systemd (Type=notify,
WatchdogSec): `kino.notify` шлёт `READY=1` / `STOPPING=1` в настоящий
Unix-датаграмм-сокет по пути из `NOTIFY_SOCKET`. Нативный `socket` (AF_UNIX)
работает и в тестовой среде — заглушечный модуль `kino/socket.py` и
`sitecustomize` удалены (журнал ревизии, действия #27–#28).

## О кнопке «stop»

В админ‑панели доступна команда **«stop»** (`nav:stop`). При её вызове вызывается `kino.notify.stopping()`, которое отправляет `STOPPING=1` в systemd и отображает пользователю сообщение о мягкой остановке процесса.
