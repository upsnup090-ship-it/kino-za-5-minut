33. БАГ: судья не повторяет запрос при обрезке. Лог сессии 1: «судья обрезан по
    max_tokens (2048)» + «ответ обрезан, спасены поля: [verdict, headline, text, ...]».
    Лестница `_judge_budgets(2048) = [2048, 16384]` есть, но `_request_judge`
    возвращает salvage как успех (parsed is not None), и `judge()` выходит из цикла
    на первой ступени — вторая ступень (16384) недостижима. Итог: правки судьи
    взяты из обрезанного JSON, хвост (drop_fields, поздние формат-поля) теряется.
    У черновика эта защита есть (обрезка ≠ успех), у судьи — нет.
    → ЗАКРЫТО (этот коммит): `_request_judge` возвращает третий элемент truncated
    (finish_reason="length"); `judge()` принимает только целый ответ, обрезанный
    держит запасным (`best_truncated`) и повторяет со следующей ступенью; если все
    ступени и фолбэк-модель обрезаны — отдаёт самый полный спасённый вариант с
    предупреждением. Целый ответ фолбэк-модели предпочитается спасённому.
    Тесты: tests/test_judge_budget.py (5), обновлены test_formats (сигнатура) и
